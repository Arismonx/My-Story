# Fix bugs – My Story

เป้าหมาย: $ARGUMENTS

## 1. อ่านบริบท
1. อ่าน `docs/BUGS.md` ทั้งไฟล์ และ `docs/BLUEPRINT.md` (หลักการ + data model)
2. ถ้าผู้ใช้รายงานบัคในแชทแทนที่จะเขียนในไฟล์ → เพิ่มลง Inbox ก่อน แล้วทำต่อตามขั้นตอน

## 2. Triage – ย้าย Inbox → Open
หารหัสล่าสุดจากทั้งไฟล์ (`grep -o 'BUG-[0-9]*' docs/BUGS.md | sort -V | tail -1`) แล้วรันเลขต่อ ห้ามใช้เลขซ้ำ
แปลงแต่ละรายการเป็นรูปแบบนี้ (เก็บข้อความต้นฉบับของผู้ใช้ไว้ใน "รายงาน"):

```markdown
### BUG-001 · <สรุปสั้นๆ>
- **รายงาน:** YYYY-MM-DD · v<เวอร์ชันที่ผู้ใช้ระบุ หรือ ?> · <อุปกรณ์ ถ้ามี>
- **ความรุนแรง:** 🔥 / ⚠️ / 💬
- **อาการ:** <ข้อความผู้ใช้>
- **วิธีทำให้เกิด:** <ถ้ามี>
```
ประเมินความรุนแรงเองถ้าผู้ใช้ไม่ได้ใส่ (ข้อมูลหาย = 🔥) แล้วเรียงบัคใน Open ให้ 🔥 อยู่บนสุด

## 3. แก้ทีละตัว (🔥 ก่อน)
1. **หาสาเหตุจริง:** อ่านโค้ดที่เกี่ยวข้อง ไล่ data flow `NotesApp → useNotes → NoteRepository → IndexedDB` ห้ามเดา
2. ถ้าข้อมูลไม่พอจะหาสาเหตุ → ย้ายไป **⏸️ Needs info** พร้อมเขียน `- **ต้องการข้อมูล:** <คำถามที่ชัดเจน>` แล้วข้ามไปตัวถัดไป
3. แก้แบบตรงจุดที่สุด ไม่ refactor เกินจำเป็น และห้ามทำให้โน้ตที่มีอยู่หาย
4. ตรวจ:
   ```bash
   source ~/.nvm/nvm.sh && nvm use
   npm run lint
   NEXT_PUBLIC_BASE_PATH=/my-story npm run build
   ```
   ไม่ผ่าน = ยังไม่เสร็จ ห้ามย้ายไป Fixed
5. ย้ายไป **✅ Fixed** (ตัวล่าสุดอยู่บน) และเพิ่มบรรทัดต่อท้าย:
   ```markdown
   - **สาเหตุ:** <อธิบายสั้นๆ ภาษาคน>
   - **แก้ไข:** <ทำอะไร> (`src/...`)
   - **แก้ใน:** next · YYYY-MM-DD
   - **ทดสอบ:** <ทดสอบยังไง และสิ่งที่ยังต้องให้ผู้ใช้ลองบนเครื่องจริง เช่น iPhone>
   ```
6. `CHANGELOG.md` → ใต้ `## [Unreleased]` › `### Fixed` เพิ่ม `- <สรุป> (BUG-xxx)`

## 4. สรุปให้ผู้ใช้
- ตาราง: รหัส · สรุป · สถานะ (Fixed / Needs info) · ไฟล์ที่แก้
- สิ่งที่ผู้ใช้ต้องลองบนอุปกรณ์จริง
- แนะนำ `/release patch` ถ้ามีบัคที่แก้แล้ว
- ถ้าบัคที่แก้เป็นเพราะการออกแบบ (ไม่ใช่โค้ดพิมพ์ผิด) → เพิ่มแถวใน Decision log ของ BLUEPRINT ด้วย
